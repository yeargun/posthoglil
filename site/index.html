Control. The same harness timed PostHog’s build against an identical copy of itself: 3 of 37 rows showed a difference, about what a 95% interval allows, so changes of one or two percent are within noise. Import is slower for the modules that define most of their functions as top-level arrows, which V8 parses more slowly in module code; it is a one-time cost of a fraction of a millisecond.

Method

How it was
measured.

The same upstream code on both sides, every file published, and one LilScript compilation per codec.

  • Upstream builds. PostHog’s build: Rolldown, then Terser 5.51.2 with posthog-js’s own compress and mangle settings (private _ names mangled, its reserved list kept). esbuild 0.28.2 bundle and minify. Oxc: Rolldown 1.2.12 bundle with minify. All target ES2020; posthog-js’s published npm files target older browsers with ES2015-level syntax, which is not what is compared here.
  • LilScript builds. One compile per codec: the raw cell comes from a build that targets raw bytes, the gzip cell from one that targets gzip, the Brotli cell from one that targets Brotli. Compiler: LilScript d8f79ed5. The builds assume what PostHog’s own Terser settings already assume: built-ins are not patched (unsafe_*), property reads have no side effects (pure_getters), _ names are private (its property mangling), no value is document.all, and object copies never carry a __proto__ key.
  • Codecs. Node’s zlib: gzip level 9; Brotli quality 11, window 22. Sizes are recomputed from the published files before this site is built, and only wins are published.
  • Scope. Seven submodules, each measured on its own. This is not the whole SDK, and not a measurement inside an application bundle.
