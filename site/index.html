02 / Runtime

Bytes are only half the story.

Installed application bundles are compared with the original npm SDK. The practical non-regression check uses a predeclared 2% slowdown bound and a one-sided 95% interval. Separate compiler-objective measurements use the optimized-original control. Lower time is better.

What these measurements include

Module import measures parsing, evaluation and module scheduling from a fresh Blob URL; it excludes downloading the source. Init uses memory persistence, autocapture and bootstrapped flags, with recording disabled. Capture measures preparation and queueing of 1,000 events, after 100 warmup calls, and asserts all 1,000 were accepted. A separate workload prepares and queues 100 exceptions after 20 warmups, using preconstructed simple errors, caused errors and aggregates with fixed stacks; every sample asserts 100 accepted exceptions. Upload, ingestion and replay processing are not timed. These are exploratory microbenchmarks, not end-user latency guarantees.

03 / Integration

Keep your application code.

The preview preserves PostHog’s package layout and canonical declarations. Install it under the posthog-js dependency name so existing imports and React bindings share the same instance.

Loading preview install command…
import posthog from 'posthog-js'
import { PostHogProvider } from 'posthog-js/react'

posthog.init('your-project-token', {
  api_host: 'https://us.i.posthog.com'
})
posthog.capture('checkout', { plan: 'pro' })

Only the root and posthog-js/full/no-external entries contain LilScript internals. Other subpaths remain exact upstream runtimes. The existing @itslil/posthog-js utility package is a separate API.
