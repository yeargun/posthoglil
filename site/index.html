posthog-js 1.435.8 · seven submodules · LilScript

Same behaviour. Same API. Smaller.

We rewrote seven submodules of posthog-js in typed LilScript and compiled them with the LilScript compiler. Each one is compared, on its own, with PostHog’s own build of the same code: Rolldown and Terser with the settings from posthog-js’s rollup config, including its private-name mangling. Each is also compared with esbuild and with Oxc, the minifier inside Rolldown. Every number on this page comes from the files linked next to it.

How this was measured

  • Same code on both sides. The upstream side is posthog-js 1.435.8 (commit c9d890a4), each submodule bundled from its TypeScript source with everything it imports. The LilScript side is a typed port that exports the same names. Nothing on either side is external.
  • Upstream builds. PostHog’s build: Rolldown, then Terser 5.51.2 with posthog-js’s own compress and mangle settings (private _ names mangled, its reserved list kept). esbuild 0.28.2 bundle and minify. Oxc: Rolldown 1.2.12 bundle with minify. All target ES2020. PostHog’s published npm files target older browsers with ES2015-level syntax; that is not what is compared here.
  • LilScript builds. One compile per codec column: the raw column comes from a build that targets raw bytes, the gzip column from one that targets gzip, the Brotli column from one that targets Brotli. Compiler: LilScript d8f79ed5. The builds assume what PostHog’s own Terser settings already assume: built-ins are not patched (unsafe_*), property reads have no side effects (pure_getters), _ names are private (its property mangling), no value is document.all, and object copies never carry a __proto__ key.
  • Codecs. Node’s zlib: gzip level 9; Brotli quality 11, window 22.
  • Behaviour. Upstream’s own test files run against the LilScript builds in place of the TypeScript modules. The gate: every upstream test that passes against PostHog’s bundled, mangled reference must pass against the LilScript build. This run: 1,076 of 1,076 gated tests for these seven modules passed.
  • Speed. Chromium 139.0.7258.5 (headless) on AMD EPYC 7763 64-Core Processor. Each sample is a fresh browser context on a local cross-origin-isolated page; PostHog’s build and LilScript’s alternate in ABBA order, 40 samples per module. Times are medians; the change is the median of paired differences with a 95% bootstrap interval, and a verdict is given only when that interval excludes zero. Both builds first run the same inputs and must produce identical output.
  • Scope. These are submodules measured on their own, not the whole SDK.
